# Ledger

<p align="center">
  <b>简体中文</b> | <a href="README_EN.md">English</a>
</p>

一个自用的家庭记账 App：**不用手动记账**。微信、支付宝的支付通知和银行卡短信会自动变成账目，退货自动冲抵支出，自己账户之间的转账不算收支，每月 20 号发工资就按"发工资到下次发工资"来算，每个月存多少钱有计划、每天自动出一份分析。后端 Python（FastAPI + Postgres）跑在自己家里的 NAS 上，安卓端 Kotlin + Jetpack Compose。

起因很简单：试过好几个记账 App，每个都坚持不到一个月——每笔都要手动记、还要对账。所以这个项目的目标只有一个：**让记账这件事自己发生**。

这个项目从头到尾都是跟 [Claude Code](https://claude.com/claude-code) 结对写出来的。

> 个人小项目，没有上架计划，也不保证长期维护。目前只在小米手机 + 建设银行 / 交通银行短信上真机跑过；其他银行的短信格式需要补一条规则（见下面"适配你自己的银行"）。

## 能做什么

- **自动记账**：监听微信 / 支付宝的支付通知和银行短信，原文发到你自己的服务器，由服务器解析成账目。通知被清掉或漏了，会从短信箱补；断网时先存在手机里，联网后补传，不会丢也不会重复。
- **同一笔只算一笔**：同一次付款微信通知一条、银行短信又一条，会自动合并；同一条消息重发也不会记两次。
- **退货会冲掉支出**：退款到账后自动配对原来那笔购买（支持分几次退、退一部分），那笔购买不再算支出，而且算在购买所在的账期里。
- **转账不计收支**：自己账户之间的转账、信用卡还款，不算收入也不算支出。
- **银行卡余额**：短信里的"可用余额"会自动变成每张卡的余额，资产页显示总资产；没有短信的卡 / 现金 / 钱包可以手动添加。
- **按发工资的日子算账期**：账期从每月某一天（比如 20 号）开始，不是自然月。工资不固定也没关系：发工资前按最近三次里最低的一次估算，发了以后按实际到账的算。
- **存钱计划**：设一个"每月要存多少"，把房租、给家人的钱、停车费等**固定支出**先预留出来，剩下的才是自由预算；告诉你还能花多少、每天最多花多少、照现在的速度月底能存多少。
- **每天自动分析**：服务器每天早上自己生成一份分析（昨天花了多少、预算还剩多少、异常大额、疑似订阅），手机早上推送一条通知。你不用打开 App 去"生成"。
- **花在哪里**：类别占比和涨跌、每天 / 每周的柱状图（**点柱子看那一天 / 那一周花了什么**）、花得最多的商家、最大的几笔（**点一笔可以改类别**）。点任何一个类别都能看到明细，按时间或金额排序。
- **出行单独算**：周末出门、国庆回家，建一个"出行"，那几天的油费、过路费、停车、吃饭、门票自动归进去；钱照样计入账期，但不会被当成你日常的花法去推算月底。服务器还会根据过路费、景区、酒店这类消费提示"疑似出行"。
- **出差垫付不算开销**：新建出行时选"出差"，填每天补贴和通勤补贴：那几天的机票、酒店、打车、吃饭全部记成"待报销"，**不计入月开销**，但会在资产页单独记着（不计入总资产，这是你的钱）。公司把钱打回来时，在 App 里选那笔进账，垫付的部分不算收入，多出来的补贴才记为收入。
- **自己标记哪笔是出差**：App 分不出一张机票是出差还是旅游，所以由你决定——长按任意一笔，选"归入「某某出差」"（或"移出出差"）。统计页右上角还有一个开关："不含出差"看你的日常真实开销，"含出差"把垫付也算进去，等报销到账后再自动冲抵。
- **会学习的分类**：长按一笔改一次类别，这家商户以后不管用微信还是支付宝付，都自动归到这一类，同商户其他待确认的也一起改。
- **筛选、搜索、无限下拉**：时间 / 类型 / 类别 / 转账 / 待确认，Excel 表头那样的下拉筛选；账目多了往下拉自动加载更早的。
- **一键同步**：不想常开 App 也行。长按桌面图标选"立即同步"，或把"记账同步"磁贴拖进下拉快捷开关，点一下就把漏掉的补上。
- 语音记一笔、手动记一笔、两个人共用一个账本也都支持。

## 它是怎么工作的

```
微信/支付宝通知 + 银行短信
        │  手机只负责"转发原文"（本地队列，离线也不丢）
        ▼
   你自己的服务器 /ingest ── 解析、合并、配对退款、分类、更新余额
        │
        ▼
   Postgres ── 计划 / 分析 / 每日报告 ← 手机读取显示
```

解析规则在**服务器**上，所以改一条规则、适配一家新银行，**不用重新发版 App**。无法识别的消息会原样存下来（`/ingest/failed`），照着真实样本补规则即可。

## 快速开始

### 1. 起后端

需要一台能 24 小时开着的机器（NAS、树莓派、软路由、云服务器都行）和 Docker：

```bash
git clone https://github.com/EdgeN8v/Ledger.git
cd Ledger
cp .env.example .env
# 编辑 .env：设置 POSTGRES_PASSWORD，并把 JWT_SECRET 改成一段很长的随机字符串
docker compose up -d --build
curl http://localhost:8000/health        # {"status":"ok"}
```

默认**不允许注册**（防止别人在你的服务器上建账号）。第一次创建账号时，在 `.env` 里临时加一行 `REGISTRATION_OPEN=true`，重启，在 App 里注册你和家人的账号，然后把它删掉再重启。

详细的部署、手机怎么连、备份见 [docs/deployment.md](docs/deployment.md)。

### 2. 装 App

到 [Releases](../../releases) 下载最新的 `Ledger-vX.X-debug.apk`，手机上安装（需要允许"安装未知来源应用"）。这是 **debug 签名**的包，能装能跑，仅此而已。

打开 App，登录页填你的服务器地址（比如 `http://192.168.1.10:8000/`），选"创建账本"注册第一个账号；第二个人用"加入账本"和账本邀请码（在"我的"页里）加入同一个账本。

### 3. 设置计划

底部"计划"页 → 修改计划：填"每月要存多少"、固定支出明细（房租、家人生活费、停车费等）。月收入可以不填，会按你的工资短信自动算。

## 在手机上授权

自动记账需要两个权限，都是系统级的，要你自己去开：

1. **通知使用权**：App 的"我的"页 → 自动记账 → "去开启" → 找到"记账"打开。
2. **读取短信**（用来补漏）：同一页点"允许读取短信"。

小米 / 部分国产系统还要做几件事，否则 App 会被杀掉、漏记：
- 应用信息里把"记账"的省电策略设为"无限制"，并允许自启动。
- 如果系统提示"受限制的设置"：应用信息 → 右上角三个点 → "允许受限制的设置"，再回去开通知使用权。
- 小米会默认拦住第三方 App 读银行类短信，需要在权限里允许"读取通知类短信"。

## 隐私和安全

- 这个 App **会读取你的支付通知和短信**，所有数据**只发到你自己部署的服务器**，没有任何第三方服务、没有统计、没有云端。
- 超过 12 位的数字串（身份证号、账号等有些银行短信会带）在入库前就会被打码，不会存下来。
- 服务器默认关闭注册，账本邀请码是随机的；JWT 密钥没设置会拒绝启动。
- **不要把 8000 端口直接映射到公网**：记账数据比较敏感，而且这个服务没有做 HTTPS。建议只在家里局域网用，出门时用 VPN（WireGuard / Tailscale 之类）连回家里；如果一定要公网访问，请放在带 HTTPS 的反向代理后面。
- 记得备份。`docker-compose.yml` 里附带了一个每天导出数据库的小容器（保留 14 份），记得把备份目录再复制到别处。

## 适配你自己的银行

银行短信的措辞每家不一样。目前验证过的是建设银行和交通银行（见 `backend/app/parsers.py`）。如果你的银行没被识别：

1. 在 App 之外，用接口看看哪些消息没解析出来：`GET /ingest/failed`（需要登录），或者直接看数据库 `raw_events` 里 `status = 'failed'` 的。
2. 在 `backend/app/parsers.py` 里照着现有的写一条规则；`backend/tests/test_ingest.py` 里有怎么写测试的例子。
3. 欢迎提 issue / PR，**但请先把真实姓名、卡号、金额打码**。

## 从源码构建

**后端测试**

```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt pytest httpx   # Linux/macOS: .venv/bin/pip
.venv/Scripts/python -m pytest tests                          # 43 个测试
```

**安卓**：用 Android Studio 打开 `android/`，或命令行 `./gradlew assembleDebug`。服务器地址默认是占位值，想把你自己的地址编译进去，在 `android/local.properties`（不会被提交）里写：

```properties
ledger.defaultServer=http://192.168.1.10:8000/
ledger.lanServer=http://192.168.1.10:8000/
```

## 项目结构

```
backend/    FastAPI + SQLAlchemy 后端（解析、合并、退款配对、计划、分析、每日报告）
android/    Kotlin + Jetpack Compose 安卓端（通知监听、同步队列、各个页面）
docs/       部署说明、备份脚本、截图
```

## 已知限制

- 只有安卓端；解析规则只验证过建设银行、交通银行、支付宝；微信支付通知的格式主要靠银行短信兜底。
- 月收入、固定支出里没有短信的账户（比如另一张卡付的房租）要靠你手动设置。
- 分类是关键词 + 你的修正，不是 AI；识别不准的商户长按改一次就学会了。
- 没有 iOS 版，也没有上架计划。
